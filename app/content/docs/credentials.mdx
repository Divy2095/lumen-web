# Credential provisioning limitations

An active project and usable API key are required, but their creation is not a verified public API.

## What authentication expects

A key lookup hashes the supplied secret with SHA-256 and joins an existing `api_keys` row to its project. The key must not be revoked or expired, and its project must be active. The database stores the key hash, not a secret that the website can recover.

## What is missing

No public account/project/API-key creation route was found in this committed application. There is no supported CLI provisioning command verified by this documentation task. A successful schema migration does not create an end-to-end onboarding contract.

This guide intentionally does not prescribe ad hoc INSERT statements, test-fixture secrets or a fictional signup endpoint. Provisioning needs an explicit, separately reviewed backend workflow. Until that exists, the first-request guide is conditional on already having authorized credentials.

## Two credentials, separate uses

The project API key authenticates media registration and asset/thumbnail retrieval. It belongs on your application server. The single-use upload token is issued by a successful registration and authenticates only the asset-specific upload.

Do not enter keys into this website. It has no API console and does not connect to Lumen. Once credentials and [runtime prerequisites](/docs/getting-started/prerequisites/) are satisfied, continue to [first registration and upload](/docs/getting-started/first-upload/).
