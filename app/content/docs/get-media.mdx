# GET media

GET /v1/media/:id returns the project-owned asset and optional thumbnail availability.

## Request

The ID is the asset ID from registration. A project API key is required via Bearer or `x-api-key`. No request body or special Content-Type is required.

```bash
curl --fail-with-body -sS \
  'http://localhost:3000/v1/media/<asset-id>' \
  -H 'Authorization: Bearer <project-api-key>'
```

## Success response

200 JSON. This illustrative example shows a current thumbnail output; values are placeholders rather than an observed processing result.

```json
{
  "id": "<asset-id>",
  "project_id": "<project-id>",
  "status": "ready",
  "original_filename": "clip.mp4",
  "mime_type": "video/mp4",
  "file_size_bytes": 2048,
  "uploaded_bytes": 2048,
  "created_at": "2026-11-12T12:00:00.000Z",
  "updated_at": "2026-11-12T12:00:10.000Z",
  "thumbnail": {
    "status": "ready",
    "url": "/v1/media/<asset-id>/thumbnail",
    "mime_type": "image/jpeg",
    "width": 640,
    "height": 360,
    "file_size_bytes": 12345,
    "created_at": "2026-11-12T12:00:11.000Z"
  }
}
```

Without a current output, queued and processing thumbnail jobs both map to `{"status":"processing"}`; a failed job maps to `{"status":"failed"}`. Other cases omit `thumbnail`. The interface mentions `not_found`, but this is not a promise that a `not_found` object is actually serialized.

Ingestion `ready` does not mean the thumbnail or metadata job completed. There is no full public extracted-metadata object, generic job list, transcoding configuration or rendition list in this committed response. See [metadata extraction](/docs/guides/metadata-extraction/).

No UUID parameter schema is declared on this route. Use returned asset IDs; malformed IDs can cause database conversion errors handled as sanitized 500s, rather than a guaranteed 400/404. All values below are illustrative; examples were checked against source, not captured from a running backend. Replace IDs and credentials with your own authorized values. Review [onboarding blockers](/docs/project/known-limitations/) before executing requests.
