# POST media

POST /v1/media creates a project-owned MP4 upload intent and returns its single-use upload credentials.

## Request

Authenticate with a project API key using Bearer authorization or `x-api-key`. Send `Content-Type: application/json` and the required JSON fields. No route parameters are present.

```bash
curl --fail-with-body -sS http://localhost:3000/v1/media \
  -H 'Authorization: Bearer <project-api-key>' \
  -H 'Content-Type: application/json' \
  --data '{"original_filename":"clip.mp4","mime_type":"video/mp4","file_size_bytes":2048}'
```

The 2048-byte value is illustrative; for an actual upload calculate the real file size as shown in [first registration](/docs/getting-started/first-upload/#register-the-file).

Only these fields are part of the committed request contract. The schema disallows additional properties; framework validation can remove or reject extra fields depending on its configuration. Do not send unreleased transcoding or job parameters.

## Success response

201 JSON. Asset ingestion is `uploading`; no file bytes have been received. The token is issued here, not through a separate public credential endpoint.

```json
{
  "id": "<asset-id>",
  "project_id": "<project-id>",
  "status": "uploading",
  "original_filename": "clip.mp4",
  "mime_type": "video/mp4",
  "file_size_bytes": 2048,
  "uploaded_bytes": 0,
  "created_at": "2026-11-12T12:00:00.000Z",
  "upload_token": "<issued-upload-token>",
  "upload_url": "/v1/media/<asset-id>/upload",
  "upload_expires_at": "2026-11-12T13:00:00.000Z"
}
```

All values below are illustrative; examples were checked against source, not captured from a running backend. Replace IDs and credentials with your own authorized values.
